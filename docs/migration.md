# 合并与迁移

## 合并到现有菜单

1. 使用 `examples/self-head.yml` 中完整的 `Icons.H` 替换现有菜单的 `Icons.H`，保留其他图标、布局、标题及菜单选项。布局中应有可点击的 `H`。
2. 保留 H 的 `update`、显示与完整 `actions.left`，不要叠加旧购买命令、确认页、额外收费或成功提示。`head:%player_name%` 用于显示，发放动作中的 `head:%player_name%` 用于本人头像物品。
3. 按当前 TrMenu 的加载流程加载菜单。在受控环境验证有余额、余额不足、真实头像纹理及满背包行为。静态配置验证不能替代这些验证。

示例是完整的独立单图标菜单；合并时只复制 `Icons.H`，不要用示例的单行布局覆盖现有菜单。

## 旧命令兼容

原 `plugin.yml` 声明主命令 `/nomiheadbuy`，别名 `/nomiheads`，权限 `nomiheadbuy.use`（默认 true）。精确字段与来源哈希见 `legacy-entries.json`。确认子命令是旧 Java 行为，不是独立声明的命令。

如需兼容，后端应在受控命令绑定中将这两个无参数入口导向已有头像菜单，由玩家左键触发 H。菜单标识须使用后端实际菜单标识，不能凭示例猜测。绑定仅打开菜单，不扣费、不发物、不代理旧确认流程。旧 `confirm`、`cancel` 及其他带参请求不应转发为购买动作；控制台请求不应借用玩家身份。

先核实命令占用与权限策略，避免旧插件仍注册入口时产生冲突。兼容绑定和旧 JAR 退役应由后端协调执行；本仓不自动修改命令注册。

## 退役旧插件与数据保留

配置替代并完成必要核验后，在维护窗口正常停止服务器，仅退役旧 NomiHeads 运行 JAR，再启动并确认菜单与兼容入口正常。保留经济服务、TrMenu 及其他插件依赖。

保留旧插件数据目录、交易日志、证据与未决交易记录。不要清锁、删除日志或修改真实旧交易数据；未决交易结合经济流水与库存人工处理，卸载插件不代表交易问题已解决。

本仓配置交付不执行卸载，也不代表线上旧 JAR 已退役。真实交易与纹理结果须由有本人认证权限的操作者核验后单独记录。
