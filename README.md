# NomiHeads 1.0.0（历史实现）

旧版独立插件不再推荐用于新部署。仓库与历史源码保留，供旧版复现、问题追溯及交易核对，不删除仓库。

目标是由 TrMenu 原生动作接替本人头像购买，费用唯一归菜单负责，不新增购买插件或交易框架。现有 GiveItem 与 Heads 已核实存在，但二者的物品构建路径不同，不能声称已直接复制完整 profile。下文说明原生迁移规则、切换条件及待验证边界。当前仍是离线迁移方案，不代表原生替代已部署或旧插件已卸载。

## 迁移与卸载条件

迁移后的购买规则是：在 PersonalInfo 菜单中普通左键点击头像，直接扣 100 米粒并发放本人头像，不再二次确认，也不使用聊天 nonce 或确认子页。费用唯一归 TrMenu，正常提示仅“购买成功”或“余额不足”。

切换核验以直接购买为准：

- 保留既有样式与其他业务，替换头像 H 的动作及点击提示，不调用旧购买命令。
- 原生余额条件通过后扣费、发放，GiveItem 同步返回后才提示购买成功；不把动作排队视为发放完成。
- 不新增空位门槛；GiveItem 会将装不下的剩余物品丢到玩家脚下。实际纹理按安装版 skullOwner 路径核验，不承诺完整 profile 复制或换肤立即生效。
- 原生 take-money 丢弃扣款回执，异常按流水和库存核对，不新增退款、钱包或日志框架。

已完成的验证限于离线配置与调用链；目标运行库仍有缺失类，需补齐匹配的运行依赖后继续验证。目标端菜单运行、真实钱包、真人头像外观与拾取均未验证，因此迁移尚未完成，不能据此认定原生替代已部署或旧插件已卸载。

满足上述条件后，正常停止服务器，仅移走 NomiHeads 的运行 JAR，再启动并确认菜单不依赖旧插件。不要移走其他插件或依赖。保留旧交易日志、证据及插件数据供核对；未决交易须结合经济流水和库存结果人工核验，不因卸载而视为已解决，不直接清锁或删除日志。

## 旧版 1.0.0 构建复现

以下仅用于历史版本复现，不作为新部署建议。旧版使用玩家现有 profile，通过 `/nomiheadbuy`（别名 `/nomiheads`）发起购买确认，依赖 Vault 兼容经济服务及支持玩家实体调度的 Paper/Folia。

准备 JDK 25 与私有依赖目录；依赖仅参与编译，不打包进插件。目录应包含唯一一份路径中含 `stable` 的 Purpur 26.3 API JAR、Vault 兼容 API 及 API 所需运行库。

```sh
python3 build.py --deps-dir /path/to/private-deps --test
# 或设置 NOMI_DEPS_DIR 后运行 python3 build.py --test
```

输出为 `build/NomiHeads-1.0.0.jar`；`--test` 运行领域断言，无需启动服务器，不能替代菜单迁移或真人验收。
